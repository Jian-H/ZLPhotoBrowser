# 涂鸦笔迹漂移、分裂排查记录

日期：2026-11-13。检查基线：`fc0cda3`（Release 5.0.6）。

## 结论

已在当前代码中复现一个能够解释视频现象的确定性缺陷：**分块缓存的逻辑尺寸没有对齐实际位图像素，每次收笔合并都会重新缩放已有笔迹，形成累积漂移；相邻分块更新次数不同，导致跨分块笔画错位、断裂。**

该问题位于 `ZLDrawCanvasView` 的缓存渲染链路。无需真实触摸、预测触点、捏合或滚动，仅向画布提交固定坐标的笔画即可复现。

用户截图为 iPhone 16 Pro / iOS 18.6.2。用户视频未提供应用构建号，因此尚不能直接核对线上包使用的具体源码版本。当前验证环境为 iOS 26.5 模拟器，尚未在该 iOS 18.6.2 真机上完成回归。

## 视频观察

视频约 11.64 秒。前段已有红色 `point at...`、`指着...`；约 3 秒开始在下方继续写字时，上方已经结束的笔迹也出现形态和位置变化。背景图片没有对应的整体移动。

这符合“新笔画更新同一区域缓存，连带改变旧笔迹”的特征。仅修改触点坐标、预测点或 Pan 识别阈值，无法解决旧笔迹随后续笔画变化的问题。

## 根因与数值证据

原实现：

1. 每块的基础尺寸为 256 个画布单位。
2. 为防止粗笔画在块边缘被裁切，增加 `renderPadding`，其中含笔宽换算产生的小数。
3. 使用带小数的 `renderRect.size` 创建 `UIGraphicsImageRenderer`。实际位图必须使用整数像素。
4. 下一笔提交时，用 `previous.draw(in: ...renderRect.size)` 将旧位图绘入逻辑尺寸，造成重复缩放、插值。
5. 每次只更新与新笔画相交的块，所以不同块累积误差不同。

在独立模拟器探针中，使用 `pathWidth = 6.123`、`defaultLinePath = 2.345`、`ratio = 1`：

| 参数 | 原实现 | 修复后 |
| --- | --- | --- |
| padding | 6.234 | 对齐后该块边距为 6⅓ |
| 请求/显示的位图宽度 | 268.468 | 268⅔ |
| 3× 下实际位图宽度 | 806 像素，即 268⅔ | 806 像素，即 268⅔ |
| 下一次合并 | 268⅔ → 268.468，重复缩放 | 尺寸一致 |

测试先画一个 `(100,100) → (110,110)` 的标记，再画一条跨越 `x = 256` 接缝的横线。随后在同块其他位置连续提交 100 笔，均不接触原标记。

| 后续提交次数 | 原实现标记质心 (x, y) | 修复后标记质心 (x, y) |
| --- | --- | --- |
| 0 | (104.7093, 104.7092) | (104.8333, 104.8334) |
| 10 | (104.3055, 104.3055) | (104.8333, 104.8334) |
| 100 | (100.6737, 100.6743) | (104.8333, 104.8334) |

原实现横、纵方向各漂移约 4.04 个画布单位。这里的单位属于归一化画布，实际屏幕位移还取决于图片显示比例与缩放倍数。修复后旧笔迹区域的 RGBA 像素逐字节一致，并与从原始路径完整重绘的结果一致。

像素密度、笔宽、图片比例会共同影响小数取整误差，能够解释不同设备或图片下的表现差异。本次同参数 2× 探针未出现累积位移；这不能推导出所有 2× 场景均不受影响。

通过 Git 历史定位，相关分块合并逻辑在 `87fab47`（2026-09-21）引入，检查基线仍保留。后续缩放手势及预览隐式动画修复没有处理此尺寸不一致问题。

## 修复

修改 `Sources/Edit/ZLDrawCanvasView.swift`：

- 按固定的渲染像素密度，将每个带边距的渲染矩形向外对齐到整数物理像素。
- 位图创建显式采用同一个像素密度。
- 图片视图的偏移使用实际对齐后的原点差，保证显示、合并、完整重绘与导出采用一致的矩形。

同时修复一个独立的尺寸缓存缺陷：原先只比较分块总数以决定是否复用。画布从 `600×800` 改为 `650×850` 时，两者都是 `3×4` 块，但末行、末列尺寸应该改变。原实现继续使用旧矩形，导致 `(635,835)` 的笔迹无法显示或导出。现在画布尺寸改变时会重建分块。
