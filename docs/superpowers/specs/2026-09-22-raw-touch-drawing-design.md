# 原始触点驱动的涂鸦输入设计

## 目标

使涂鸦从手指真实落点起即时可见，并完整保留有效的原始触点轨迹。快速、短小、连续的笔画不依赖 `UIPanGestureRecognizer` 的识别阈值。

## 不变约束

- 保持 `ZLDrawPath`、`ZLEditImageModel.drawPaths`、`ZLEditorManager`、撤销/重做及导出接口不变。
- 保持单指绘制、贴纸优先、滚动视图失败依赖和工具栏点击区域行为不变。
- 轻触保留为圆点；预测触点只用于屏幕预览，不写入持久化路径。
- 不新增依赖，不改变公开 API。

## 输入状态机

`ZLDrawTouchCollector` 继续在控制器根视图观察未过滤的触点。它只在 `touchesBegan` 时判定触点是否处于可绘制图片区域，并为该触点保持资格到终止事件。

控制器维护一个仅在单次触摸内存活的绘制会话：

1. `began`：创建 `ZLDrawPath`、保存至活动状态并立即显示首点预览。
2. `moved`：将每批 coalesced 真实触点增量追加到活动路径，并刷新活动预览。预测点可延展预览，但不会进入 `ZLDrawPath`。
3. `ended`：先追加终止批次真实触点，再提交同一活动路径到 tile 缓存和编辑历史。
4. `cancelled`：提交已经接收到的真实片段，避免系统取消导致用户已画出的部分消失。

`UIPanGestureRecognizer` 不再创建、补全或提交 `ZLDrawPath`；它只负责保持既有的工具栏显隐时机和滚动/贴纸手势关系。其状态不会影响原始触点会话。

## 渲染与状态

- 活动路径继续使用 `ZLDrawCanvasView` 的独立 `CAShapeLayer`，每次只更新当前路径。
- `ended/cancelled` 时，将路径提交给相交 tile；不重绘历史路径。
- 会话结束后清除活动路径、预测点和触点缓存，防止跨笔画串联。
- 如果构建路径所需的几何比例无效，则不创建会话；这是布局尚未就绪时唯一允许丢弃的情况。

## 测试

- 提取不依赖 UIKit 触点构造的会话/样本回放单元，验证首点即时创建、短轨迹逐点提交、预测点不持久化以及取消时保留实际样本。
- 保留现有路径点保真与 tile 跨界渲染测试。
- 运行 SwiftPM iOS XCTest 和 `ZLPhotoBrowser` Simulator 构建。
- 在真机上手测：工具栏显示时的极短笔画、连续快速笔画、快速连笔、撤销/重做、橡皮擦与画布缩放。

## 风险与缓解

- 原始触点会比 Pan 更早开始：资格判定仍限定为涂鸦工具、非橡皮擦、贴纸隐藏且落点位于画布，避免工具栏点击进入绘制。
- 系统可能在竞争手势下取消触点：取消时提交已收到的真实片段，优先保证所绘即所得。
- 工具栏显隐与输入解耦：Pan 仍保留原有显隐动作，不再拥有路径状态，避免重复提交。
